# Завершение задачи

Для затронутого модуля (`<m>` = `platform`, `services/order`, ...):
1. `task -d <m> test` — юнит, без Docker.
2. `task -d <m> test-integration` — если есть `integration`-тесты или менялся код под ними.
3. `task -d <m> lint` — линт идёт с `build-tags: integration`.
4. Стабильность асинхронных тестов: `go test -race -shuffle=on -count=5 -tags=integration <pkg>`.
5. Перед сдачей модуля `integration`: `task cover` (пороги: каждый пакет `platform` и `domain`/`service` ≥ 80%, `total` ≥ 70%; `.testcoverage.yml` не менять).
6. Отметить чекбоксы задачи в `spec/changes/<...>/todo.md`.
7. Показать краткое резюме и остановиться: коммит только по явной команде. Найденные баги и изменения боевого кода перечислить в резюме.
8. Найденный баг: сначала красный тест, затем исправление; изменение контракта — только после согласия.

Тест, описывающий уже существующее поведение, красным не бывает: проверять мутацией (сломать боевой код, убедиться, что тест падает, откатить `git checkout -- <file>`).
